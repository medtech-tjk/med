# Закрытие оставшихся пунктов аудита

Запрос владельца: «сделай все» — реализовать оставшиеся исправления без смены дизайна, сравнения товаров или объявлений о переезде.

## Решения

- Сборка: заменить CRA/CRACO на Vite, тесты перенести на Vitest; оставить каталог build/ и действующий Express-сервер. Удалить неиспользуемые зависимости, выполнить актуальный audit.
- Админка: мастер-ключ только через ADMIN_TOKEN в окружении; после входа выдавать случайную ограниченную по времени серверную сессию. Cookie HttpOnly, SameSite и Secure для production; CSRF-проверка для изменений. Сессии общие для workers в MongoDB, выход отзывает сессию. Мастер-ключ не сохраняется в localStorage.
- API передавать через same-origin Express proxy; не полагаться на сторонние cookie разных доменов. Не передавать непроверенные forwarded-заголовки.
- Ограничения: rate limiting входа и заявок, лимит тела/файла, реальная проверка содержимого изображений/PDF. Production rate limit с общим хранилищем, локальный вариант только для разработки/тестов.
- БД: один database.py и единый DB_NAME; ничего не переименовывать в действующей БД. Добавить индексы и инструкции резервного восстановления.
- Каталог: серверный endpoint пагинации, count, сортировки и фильтров; отдельные facets. Клиент не считает весь каталог по первым 100 товарам. Проверить результаты за пределами первой сотни и точность фильтров.
- Разметка: убрать неподтверждённые обещания бесплатной доставки и возврата за 14 дней из JSON-LD.
- Проверки: unit/API regression, временная тестовая БД при доступности, браузерные сценарии, accessibility scanner и Lighthouse. Зависимости backend — отдельный аудит.

## Последовательность

1. Записать исходные SHA256; независимые задачи сборки и защиты загрузок/лимитов выполняются отдельными агентами по скиллу dispatching-parallel-agents.
2. Основной агент реализует database, sessions/CSRF/proxy и серверную пагинацию с тестами.
3. Интегрировать изменения, проверить миграцию и совместимость, исправить найденные регрессии.
4. Выполнить проверки и независимый финальный review, обновить AUDIT.md по фактам.

## Границы

Никаких записей в production и реальных уведомлений во время тестов. Публикация и изменение секретов рабочего deployment — отдельный завершающий шаг с конкретным проверяемым результатом. Если настройки/доступ отсутствуют, локально подготовить всё необходимое и точно обозначить, что требует внешнего окружения. Отсутствие доступа не считается успешной интеграционной проверкой.
