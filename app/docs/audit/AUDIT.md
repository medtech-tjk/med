В локальном проекте проверены frontend React, backend FastAPI, публичные маршруты, форма/корзина, административная авторизация, SEO-выдача для роботов, ассеты и конфигурация запуска. ## Публикация

1. Развернуть frontend и backend вместе: favicon нужен и в prerender HTML. Собрать через `npm ci && npm run build`, запустить `node server.js`. Существующий production не изменялся.
2. На frontend задать BACKEND_URL и PROXY_SHARED_SECRET. На backend задать тот же PROXY_SHARED_SECRET, FRONTEND_PROXY=true, MONGO_URL, DB_NAME, ADMIN_TOKEN (минимум 32 случайных символа), REDIS_URL и SITE_URL=https://medtech.tj. Настроить TRUST_PROXY только после подтверждения реальной схемы ingress. Секреты задаются в серверном secret store, не в REACT_APP_*.
3. Проверить реальный каталог, форму и админку на staging. Подтвердить новые серверные ограничения формы и цены из БД.
4. После публикации проверить `/favicon-96x96.png`, `/favicon.ico`, HTML главной обычным User-Agent и Googlebot, `/sitemap.xml`, контакты и карту.
5. Запросить повторную индексацию главной в Google Search Console. Google самостоятельно решает, показывать ли favicon; обработка может занять несколько дней или недель. Источник: https://developers.google.com/search/docs/appearance/favicon-in-search .

Источники реализации: существующий логотип проекта; официальная документация Google Search Central; README DOMPurify https://github.com/cure53/DOMPurify .
